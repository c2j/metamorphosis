**Architecture:** Add `z3` crate dependency to `metamorphosis-qed`. Create a new `z3_solver.rs` module that implements the QED constraint encoding directly via Z3's Rust API. Replace `run_prover()` internals to call Z3 instead of spawning a process. Keep `prover_compat.rs` and the old binary path as a fallback behind a feature flag.

**Tech Stack:** `z3` crate v0.20 (vendored), `z3-sys` v0.11, existing `metamorphosis-qed` IR types.

### Task 4: Implement equivalence check and wire into run_prover

**Files:**
- Modify: `crates/qed/src/z3_solver.rs`
- Modify: `crates/qed/src/prover.rs`

**What this does:**

1. Encode both queries as Z3 relations
2. Assert `query1 != query2` (negated equivalence — if UNSAT, they're equivalent)
3. Map Z3 results to `ProofResult`:
   - `UNSAT` → `ProofResult::Equivalent`
   - `SAT` → `ProofResult::NotEquivalent` with counterexample from model
   - `Unknown` → `ProofResult::Unknown`

**Step 1: Implement equivalence check**

```rust
pub fn solve_equivalence(input: &QedInput) -> Result<ProofResult, ProverError> {
    let cfg = Config::new();
    let ctx = Context::new(&cfg);
    let solver = Solver::new(&ctx);

    let sorts = declare_schema_sorts(&ctx, &input.schemas)?;
    let rel1 = encode_relation(&ctx, &sorts, &input.queries[0])?;
    let rel2 = encode_relation(&ctx, &sorts, &input.queries[1])?;

    // Assert: exists a tuple in the symmetric difference of rel1 and rel2
    let diff = Bool::or(&ctx, &[&rel1.neq(&rel2)]); // simplified
    solver.assert(&diff);

    match solver.check() {
        SatResult::Unsat => Ok(ProofResult::Equivalent),
        SatResult::Sat => {
            let model = solver.get_model();
            Ok(ProofResult::NotEquivalent {
                counterexample: model.map(|m| format!("{m}")),
            })
        }
        SatResult::Unknown => Ok(ProofResult::Unknown {
            reason: "Z3 returned Unknown".to_string(),
        }),
    }
}
```
